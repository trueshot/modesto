The Problem with HTTP per Frame

Don't do this for real-time tracking: 
while True:
    response = requests.get(f"http://localhost:8001/api/cameras/lodge/{cam}/capture")
    frame = decode(response.content)
    detect_apriltags(frame)
    # Each iteration: 2-6 seconds latency!

Each HTTP request to /capture opens a new RTSP connection, grabs one frame, closes it. That's 2-6 seconds per frame. For 16 cameras, that's 30+ seconds per scan.

The Solution: Persistent RTSP Connections

For real-time AprilTag detection (inner loop): 
# Keep connection open, read frames continuously
cap = cv2.VideoCapture("rtsp://admin:@192.168.0.165:554/ch01/0")

while True:
    ret, frame = cap.read()  # ~50-100ms per frame
    if ret:
        tags = detect_apriltags(frame)
        process_tags(tags)

A persistent VideoCapture connection gives you frames in ~50-100ms instead of 2-6 seconds. That's 20-60x faster.

NVR Concurrency Limit

Critical: The GW Security NVR at 192.168.0.165 can only handle 2 concurrent RTSP connections reliably. More than that causes failures or timeouts.

Options for 16 cameras with 2-connection limit:

  1. Round-robin: Keep 2 connections, cycle through cameras
  2. Priority cameras: Keep persistent connections to high-value positions (bay doors), poll others
  3. Event-driven: Connect on-demand when activity detected
